# 샘플 보일러플레이트 반출 패키지 작성 요청문

아래 요청문을 원본 프로젝트의 에이전트에게 전달합니다. 요청문 자체로 작업할 수 있으며, [작성 규칙](./authoring-rules.md)을 함께 전달하면 세부 기준도 확인할 수 있습니다. 이 저장소에 접근할 수 있다고 가정하지 않습니다.

```text
이 프로젝트의 코드·설정·접근 가능한 작업 기록을 참고해, 다른 프로젝트를 시작할 때 재사용할 최소 샘플 보일러플레이트를 만들어줘. 목표는 원본 제품의 문서나 업무 규칙 보관이 아니라 독립 실행 가능한 샘플과 그 샘플의 설명·작업 지침을 만드는 것이야.

1. 작업 범위와 결과 폴더
- 적용 AGENTS와 git status를 먼저 확인하고 사용자 변경을 보존해줘.
- 원본 유형을 mobile-app, server, server-wui, electron-app 중 실제 구현에 맞게 선택해줘. 불명확하면 조사 후 필요한 부분만 질문해줘.
- 결과는 원본 프로젝트의 boilerplate-export/유형명/ 안에만 작성해줘. 예: boilerplate-export/server-wui/.
- 원본 루트 README·AGENTS·소스·의존성·잠금 파일·워크스페이스·배포 설정은 수정하지 마. 기존 반출 폴더가 있으면 작업 내용을 확인하고 그 안에서 갱신해줘.
- 완료 후 유형명 폴더 하나만 문서 저장소의 02.Boilerplates/ 아래로 복사할 거야. 복사 후 파일 수정·경로 변경 없이 사용할 수 있게 해줘.

2. 산출물 구조
boilerplate-export/유형명/
  README.md
  project-agents.md
  docs/boilerplate.md
  boilerplates/minimal/README.md
  boilerplates/minimal/의 실제 소스·버전·의존성·잠금·실행·테스트 설정

- project-agents.md는 샘플 프로젝트 작업용 AGENTS 지침의 보관 파일명이야. 문서 저장소에 복사할 때 자동 적용되지 않게 이 이름을 사용해줘. 실제 새 프로젝트에 적용할 때 루트 AGENTS.md로 복사하는 방법을 README에 적어줘.
- 지침의 코드 경로와 명령은 boilerplates/minimal/을 작업 루트로 삼아 적고, 문서 링크는 project-agents.md 파일 위치에서 유효하게 연결해줘. 적용 시에는 샘플 코드를 새 프로젝트 루트로 복사하고 지침 링크도 그 배치에 맞춰 조정하도록 안내해줘.

3. 추출할 내용과 제외할 내용
- 대표 기능의 연결된 코드·버전 파일·manifest·lockfile·CI·빌드/테스트 설정을 읽고 실제 반복되는 구조·파일명·역할·의존 방향을 추출해줘.
- 원본의 장비명·업무 모델·패킷 명령·제품별 화면 순서·고정 절대 경로·개인 데이터·비밀값을 일반 규칙으로 가져오지 마.
- 새 아키텍처·라이브러리를 강제하지 말고 기존 패턴을 최소 기능 하나로 축소해 보여줘. 추가·생략한 부분은 원본과의 차이로 명시해줘.
- 문서·지침·명령은 반출 패키지에 실제 존재하는 샘플을 기준으로 작성해줘. 원본 파일을 로컬 링크로 연결하지 마. 필요한 출처는 원본 저장소의 공개 가능한 커밋·경로 텍스트 또는 유효한 고정 링크로 제한하고 민감한 자료는 제외해줘.

4. 폴더·파일 이름과 역할 설명
- 원본의 실제 폴더·파일명을 조사한 뒤 샘플의 이름을 정해줘. 대소문자·접미사·역할별 명명 규칙과 대표 예시를 설명해줘.
- docs에 샘플 전체의 직접 관리 파일 목록을 작성해줘. 각 항목에 샘플 기준 경로, 폴더/파일 역할, 주요 클래스·함수/내보내기 또는 설정 책임, 연결되는 호출자·사용처를 적어줘.
- src만이 아니라 진입점·DI/조립·모델·공유 코드·설정·스크립트·테스트·버전 파일·manifest·잠금 파일·ignore도 포함해줘. vendor·node_modules·빌드 결과는 제외해줘.
- 단순히 “기능 파일”이라고 쓰지 말고 무엇을 받고 처리·반환하는지 실제 내용을 읽어 설명해줘. 파일이 너무 많으면 역할별 표로 나누되 직접 관리 파일을 누락하지 마.

5. 각 문서의 책임
- 루트 README: 샘플 목적·핵심 동작, 기술/버전 기준 파일, 빠른 시작, 핵심 구조와 역할, 새 기능 추가 순서, 검증/빌드, 상세 문서·지침·샘플 링크, 현재 검증 상태와 제약.
- docs/boilerplate.md: 적용 범위와 출처, 버전 기준, 폴더/파일명·전체 역할 목록, 의존 방향·대표 데이터 흐름, 기능 작성 규칙, 정확한 명령, 보안/변경 경계, 새 프로젝트로 복사·치환하는 방법, 예외·검증 결과의 9개 절.
- project-agents.md: 샘플 범위, 작업 전 확인, 구조/명명/경계, 구현 원칙, 실제 실행·검증 명령, 완료·보고의 6개 절. 원본 제품에만 있는 클래스·API·명령을 지시하지 마.
- 샘플 README: 필요한 OS/CPU/런타임/SDK, 의존성 복원, 실행·예상 URL/화면/응답·종료, 테스트·빌드, 포트 변경 방법, 독립 실행 범위, 검증 결과. 긴 공통 설명은 docs로 연결하되 샘플만 복사해도 실행 안내는 읽을 수 있게 해줘.

6. 최소 실행·테스트
- 샘플 폴더만 별도 위치로 복사해도 설치·실행·테스트할 수 있게 해줘. 상위 소스·node_modules·개인 경로·운영 DB·제품 자격증명에 의존하지 마.
- 버전 파일·manifest·실제 도구로 생성한 lockfile을 포함하고 설치 결과·캐시·빌드 결과는 반출하지 마. 불필요한 생성기·설정 옵션·빈 계층·TODO는 넣지 마.
- server는 정상/잘못된 요청, server-wui는 UI→서버→결과·오류 표시, mobile은 화면·상태 변화, electron은 renderer→preload/IPC→main의 핵심 흐름 하나를 실제로 구현해줘.
- 의미 있는 작은 테스트를 포함해줘. 원본에 테스트 스크립트가 없어도 샘플에는 실제 검증 명령을 제공해줘. 샘플의 보안·입력 검증을 실행 편의를 위해 생략하지 마.
- 서버+UI는 하나의 시작 명령 또는 두 터미널 실행 순서와 종료 방법을 제공해줘. 포트 충돌 시 변경할 설정과 연동 프록시도 함께 안내해줘.

7. 완료 검증·보고
- 유형명 폴더 전체를 임시 위치로 복사하고 문서 링크를 검사해줘. 코드 블록·JSON/TOML/YAML 문법·설명과 실제 파일명·스크립트 일치도 확인해줘.
- 그 복사본의 boilerplates/minimal에서 의존성 복원·테스트·빌드·기동·종료를 검증해줘. 설치·원격 쓰기·DB 변경·배포는 현재 권한과 원본 지침을 따라줘.
- 브라우저/GUI 동작은 가능하면 실제로 확인하고 못 하면 미검증으로 적어줘. 타입 검사·HTTP 응답만으로 화면 동작까지 확인했다고 하지 마.
- OS·CPU·런타임·패키지 관리자 버전과 실행 명령·결과·미검증 이유를 남겨줘. 확인할 수 없는 과거 기록과 라이선스를 추측하지 마.
- 최종 보고에는 복사할 폴더 경로, 산출물 목록, 검증 결과, 원본 변경 여부, 남은 제약을 적어줘. 반출 패키지 밖 파일이 필요한 상태면 완료로 보고하지 마.
```
