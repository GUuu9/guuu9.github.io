# 보일러플레이트 추출·신규 제작 요청문

기존 프로젝트 추출 또는 신규 보일러플레이트 제작에 사용할 요청문입니다. 아래 작업 유형·목적·형식·출력 위치를 정해 개발자/AI에게 전달합니다. [작성 규칙](./authoring-rules.md)을 함께 제공하면 상세 기준을 확인할 수 있습니다. **기존 Composer 확장은 해당 Composer 내부 지침을 사용합니다.**

```text
다음 조건으로 독립적으로 사용할 수 있는 최소 동작 보일러플레이트와 문서·검사를 작성해줘.

작업 유형: 기존 프로젝트에서 추출 / 신규 제작 중 선택
목적·대표 동작: 실제 요구로 작성
언어·플랫폼·실행/배포 환경: 실제 요구로 작성
형식: 단독 실행형 / 조립형 중 선택
조립형의 기능 원본 참조: 부모 묶음 직접 참조 / 별도 요구로 지정 (실행·빌드 독립성과 구분)
출력 위치: 추출이면 boilerplate-export/유형명/, 신규면 지정한 새 폴더

1. 범위·조사
- 적용 AGENTS·git status·기존 폴더와 사용자 변경부터 확인하고 필요한 최소 변경만 해줘. 작업 유형·출력 위치·대표 동작이 불명확하면 확인해줘. 요청 없이 새 생성기/Composer나 외부 서비스를 추가하지 마.
- 추출은 대표 기능의 코드·호출자·테스트·설정·버전/manifest/lock·CI·정상/오류/종료 흐름을 읽고 반복 관례를 최소 독립 샘플로 줄여줘. 원본 루트 README·AGENTS·제품 소스·의존성/lock·CI/배포 설정은 수정하지 말고 결과는 반출 폴더 안에만 작성해줘.
- 신규 제작은 요구한 동작/환경에 필요한 도구·구조만 선택해줘. 원본이 없는데 출처·추출 과정·과거 검증을 만들지 마. 기존 Composer 확장 작업이면 해당 독립 저장소 내부 규칙으로 진행하고 이 요청문을 확장 계약으로 삼지 마.
- 제품 고유 장비·업무 모델·패킷·화면 순서·개인 경로·데이터·비밀값을 일반 샘플에 가져오지 마. 관찰한 사실·사용자 결정·미확인을 구분하고 라이선스·저작권은 보존해줘.

2. 결과 구조·구현
- 단독 실행형은 유형 폴더 자체를 프로젝트 루트로 하고 README.md·docs·project-agents.md·update.md와 실행 소스·설정·버전/lock·테스트를 함께 둬. 폴더 하나를 새 위치로 옮겨 원본 없이 실행할 수 있어야 해. 불필요한 compose/components/feature 명령은 넣지 마.
- 조립형을 요청했다면 묶음 관리자 영역·뼈대·구성품·생성 앱을 구분하고 형태/기능·선행/충돌·소유 파일·버전 계약을 정해줘. 생성 앱은 도구·설명·지침·필요 상태를 포함해 묶음 없이 실행·빌드가 가능해야 해. 기능 추가에 필요한 원본 참조 위치·식별자·이동 제약은 별도로 정해줘. 조립 도구는 기존 사용자 파일을 보호하고 충돌/미지원은 쓰기 전에 중단하며 실패 시 소스·manifest/lock·상태를 복구해줘. 외부 설치 부작용·캐시/산출물은 복구 범위를 구분해줘.
- 부모 묶음 직접 참조 방식은 앱을 묶음의 project/ 아래에 두고 뼈대·components에서 기능을 가져와줘. 구성품 사본을 앱에 복제하지 말고 원본 해시·활성 기능·충돌 검사 상태와 도구를 앱 Git에 보관해줘. 고정 `/project/*`·`!/project/.gitkeep` 규칙으로 생성 앱을 제외하고 .gitignore를 생성 시 수정하지 말고 앱 Git은 별도로 관리해줘. 원본이 없거나 생성 당시 해시와 다르면 앱 쓰기 전에 중단해줘. 현재 TypeScript/Flutter Composer는 이 방식이며 새 조립형에 적용할지는 위 요구를 따라줘.
- 프로젝트 기능을 components feature로 추출할 때는 폴더 전체를 복사하지 말고 파일별 포함/제외와 이유를 먼저 정해줘. 재사용 API·Service·util·공용 계약만 가공하고 입력/의존성을 주입해줘. 원본 Scene·Page·화면 전용 ViewModel/상태·라우팅·앱 DI·업무 흐름/자산은 앱에 남겨줘. 기능 설치/등록만 자동 연결하고 소비 앱 화면·DI·동의 UI는 생성하지 마. 원본 앱 없이 최소 호출자/테스트로 검증하고 README에 공개 계약·재사용 범위·앱 책임을 적어줘. 분리 불가하면 등록하지 말고 기존 학습 예제는 일괄 삭제하지 마.
- 대표 동작 하나를 실제로 구현하고 기존 패턴을 재사용해줘. 형식 때문에 빈 API·Model·Service·Repository·util/core를 만들지 마. 입력/발신자 검증·안전한 오류·시작 실패·종료/dispose·저장 마무리를 유지해줘.
- 새 권한은 플랫폼 선언·동의/거부/재시도·스토어 고지를, 데이터 형식 변경은 호환/백업/복귀를 함께 다뤄줘. 운영 자격증명·DB 없이 기본 동작을 확인할 수 있게 하고 외부 서비스가 필수라면 준비·초기화·보존 범위를 명시해줘.
- 실제 .env·키·서명·SDK·캐시·의존성 설치 결과·빌드 결과는 제외해줘. 공개 .env.example·버전 파일·실제 도구로 생성한 lock을 보관하고 첫 설치 때 lock을 만드는 형식은 이유와 후속 복원 방법을 설명해줘. lock을 손으로 꾸미거나 기존 lock 삭제로 문제를 숨기지 마.

3. 문서·지침
- README는 목적·대표 동작·버전 기준·선행 조건·빠른 시작·구조·실제 명령·검사·상세 문서·제약의 입구로 작성해줘. 가져오기 → 도구/환경 → 의존성 복원 → 실행/종료 → 검사 → 개발/배포/업데이트 순서야. 조립형만 생성/기능 추가 단계를 필요한 도구 준비 뒤에 넣어줘.
- docs는 01-name.md 순서로 시작·환경/플랫폼·구조/개발·배포·버전 관리를 안내해줘. 설치 명령·PATH·버전 선택·상태 확인·실행 위치/권한·예시/실제값·포트/기기·종료를 직접 제공하고 반출 폴더 밖 Setup/Tools를 전제로 하지 마. 실제 제공한 help·명령·기능과 README·사용 문서를 함께 맞춰줘.
- 필수/조건부/선택 도구와 준비 순서·완료 확인을 적어줘. macOS는 Git·Homebrew·nvm 전에 선택한 CLT 또는 전체 Xcode의 라이선스·최초 초기화를 확인해줘. Windows는 실제 데이터 드라이브 경로를 사용하고 프로젝트 때문에 전역 도구 기본값을 바꾸지 마.
- 구조 문서는 범위·버전·직접 관리 파일의 역할/주요 함수·설정/호출자·명명·의존/흐름·기능 작성·명령·보안/변경 경계·새 앱 적용·검증을 설명해줘. 실제 실행 경계·계층/공개 계약·허용/금지 의존·진입/조립/소유·정상/오류/종료 흐름과 실제 경로의 구조/흐름도를 담고 import와 HTTP/IPC 호출을 구분해줘. 짧은 문서마다 전체 구조를 복제하지 마.
- project-agents.md에는 범위·작업 전 확인·구조/명명/경계·최소 완결 구현/보안·실제 검사·완료/한계를 담고 작업별 선행 문서와 갱신/검사를 안내해줘. 단독형은 AGENTS.md 적용 방법, 조립형은 관리자/앱 지침 구분과 실제 생성 시 출력 방식을 적어줘.

4. 버전·보안·배포·업데이트
- 앱·보일러플레이트/구성품 구현·SDK/패키지·문서 버전을 구분하고 실제 버전 파일/manifest/lock을 기준으로 해줘. 보안/지원 이슈는 공식 권고·영향 버전/노출·조치/보류 이유·담당/재점검 날짜·마지막 정상 조합/복귀를 기록하고 무관한 전체 업그레이드를 섞지 마.
- 원본 revision/스냅샷·선택 구성·lock·도구·OS/CPU/기기·명령/결과로 정상 조합을 기록해줘. 공식 최소/최대 또는 상한 미명시/미확정과 실제 검증 최저/최고를 구분해줘. 미검증을 지원 보장으로 표시하지 마.
- 배포는 도구/계정·식별자/앱·빌드 번호/lock → 실제 빌드/산출물 → 서명·스토어/운영 배포 → 검증·보관·업데이트/복귀 순서로 설명해줘. 로컬 빌드를 제출/배포 성공으로 표현하지 마.
- 커밋이 요청되면 type(scope): 한국어 요약 형식을 사용하고 한 목적의 코드·검사·문서·이력을 묶어 저장소별로 커밋해줘. type은 feat/fix/refactor/docs/test/build/ci/chore/revert, scope는 실제 변경 영역의 소문자 kebab-case야. 본문은 필요한 이유·실제 검증·이행만 짧게 적고 update.md는 같은 제목으로 맞춰줘. 호환성을 깨면 type(scope)!:와 이행 설명을 사용하며 기존 이력·자동 merge/revert 메시지는 보존해줘.
- update.md는 커밋당 한 항목으로 최신순 기록해줘. 날짜·커밋 제목 아래 핵심 변경 1~3줄과 검증/미검증 1줄만 적고 호환성·데이터·복귀 주의는 실제 영향이 있을 때만 추가해줘. 미커밋 작업은 맨 위 한 항목에서 갱신해 커밋 전에 통합하고 중간 과정·긴 로그·반복적인 미커밋 문구는 남기지 마. 기존 이력은 오류 정정 외에는 보존해줘.
- 보일러플레이트 원본 갱신과 개발 중인 앱 반영은 별개로 안내해줘. 기존 앱을 보관하고 이전/새 원본과 사용자 코드를 비교·검증·이행하게 해줘. 강제 덮어쓰기나 구현하지 않은 자동 업데이트를 약속하지 마.
- 부모 참조형은 원본 해시와 해당 파일을 보존하고 공개 파일·문서 변경 시 기능 추가가 중단될 수 있음을 안내해줘. 원본 복원 또는 새 앱 비교·이행으로 해결하며 해시만 고쳐 우회하지 마. 기존 사본 방식 앱의 도구·상태·사본은 자동 전환/삭제하지 마.

5. 완료 검사·보고
- 결과 폴더를 별도 위치로 옮겨 원본 없이 설치·분석/타입·테스트·빌드·실행/종료를 확인해줘. 의미 있는 작은 검사를 제공하고 새 의존성은 깨끗한 설치로 확인해줘.
- 조립형은 제공한 help·생성·기능 미선택/단독/복수/순서·중복·사용자 변경 보호·미지원/충돌·실패 복구와 원본 참조 계약에 맞는 기능 추가도 검사해줘. 부모 참조형은 원본 누락/변경 시 앱 보존·묶음 전체 이동 후 추가·구성품 사본 부재·생성 폴더 Git 제외도 확인해줘. 앱만 이동해도 실행·빌드는 가능하지만 기능 추가에는 부모 원본이 필요함을 구분해줘.
- 정적/모의 검사·실제 실행·GUI/기기·권한·서명·배포·다른 OS를 구분하고 미검증은 필요한 조건/이유를 남겨줘. 설치·원격 쓰기·데이터/배포 작업은 현재 권한을 따라줘.
- 파일/역할/계약/명령과 설명, 반출 후 링크·앵커·코드 펜스·설정 문법·git diff --check를 검사하고 개인 설정/키/캐시/산출물이 포함되지 않게 해줘.
- 검증 문서에 요구사항 / 실제 파일·절 / 검증 결과 / 상태(충족·미충족·미검증·해당 없음)를 기록하고 실제 위치를 확인해줘. 테스트 통과로 문서 누락을 충족 처리하지 마.
- 최종 보고에 결과 폴더/대상 저장소·실제 변경·추출 시 원본 제품 미변경 여부·환경/명령/결과·미충족/미검증·데이터/복귀 영향을 적어줘. 실행 코드는 별도 보일러플레이트 저장소에서 관리하고 안내 저장소에 복제하지 마. commit·push·배포는 요청된 범위에서만 수행해줘.
```
