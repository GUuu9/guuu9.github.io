# 재사용 샘플 보일러플레이트 작성 규칙

## 1. 목표와 변경 범위

기존 프로젝트의 구조·명명·개발 방식을 **재사용 가능한 최소 샘플**로 추출합니다. 원본 제품의 문서·업무 규칙을 그대로 보관하는 작업이 아닙니다. 샘플은 동작하는 코드와 테스트를 포함하고 문서는 그 샘플만 설명합니다.

원본 프로젝트에서는 boilerplate-export/유형명/에만 산출물을 작성합니다. 루트 README·AGENTS·제품 소스·의존성·잠금 파일·CI·배포 설정은 수정하지 않습니다. 기존 반출 폴더의 사용자 변경도 보존합니다.

## 2. 조사와 추출

git status·적용 지침·버전/잠금 파일·manifest·CI·테스트·대표 기능의 연결된 코드를 확인합니다. 제공된 작업 기록은 현재 구현과 대조하고 접근할 수 없는 기록은 추측하지 않습니다. 관찰한 사실·사용자 결정·개선 제안을 구분합니다.

실제 반복 관례를 추출하되 원본의 MVVM·DI·Repository 등을 필요 이상 복제하거나 모든 유형에 강제하지 않습니다. 제품별 장비·화면 순서·인증 정책·패킷·절대 경로·비밀값은 일반 샘플 규칙으로 옮기지 않습니다. 위험한 기존 구현은 표준화하지 않습니다.

## 3. 반출 폴더 계약

```text
원본 프로젝트/
└── boilerplate-export/
    └── 유형명/
        ├── README.md
        ├── project-agents.md
        ├── docs/
        │   └── boilerplate.md
        └── boilerplates/
            └── minimal/
                ├── README.md
                └── 실제 소스·설정·테스트
```

유형명은 mobile-app·server·server-wui·electron-app 중 실제 목적에 맞게 선택합니다. 유형명 폴더만 이 저장소의 02.Boilerplates/로 복사하면 문서와 샘플이 바로 사용 가능해야 합니다. 상위 프로젝트·밖의 파일·개인 경로에 의존하거나 복사 후 링크를 고쳐야 하는 상태는 미완료입니다.

project-agents.md는 프로젝트 적용용 AGENTS 내용의 보관명입니다. 문서 저장소에서 자동 지침이 되지 않게 실제 AGENTS.md로 생성하지 않습니다. 샘플 코드의 명령·경로는 boilerplates/minimal 작업 루트 기준임을 명시하고 문서 링크는 보관 파일 위치에서 유효하게 작성합니다. 새 프로젝트에 적용할 때 코드·문서 배치와 AGENTS.md 복사·링크 조정 절차를 안내합니다.

## 4. README.md 작성

반출 폴더의 README는 샘플 소개와 탐색 입구입니다. 원본 프로젝트 루트 README를 복제하지 않습니다.

1. 샘플 목적·핵심 동작·제외한 범위
2. 기술 스택·버전 기준 파일과 지원 환경
3. 최소 실행까지의 빠른 시작
4. 실제 핵심 파일 트리·각 폴더의 책임
5. 샘플의 대표 흐름을 이용한 새 기능 추가 순서·파일명·테스트 위치
6. 테스트·타입 검사·빌드 명령과 작업 디렉터리
7. 최소 샘플의 독립 복사·실행 범위
8. docs·project-agents·샘플 README 상대 링크
9. 검증 상태·제약·필요한 라이선스 고지

앱 버전·도구 버전·언어 표준을 혼동하지 않고 실제 manifest·버전 파일을 연결합니다. 긴 근거·명명 표는 docs로 연결합니다.

## 5. docs/boilerplate.md 작성

아래 9개 절을 유지합니다. 해당 없음·미확인은 이유를 기록하며 존재하지 않는 구조를 만들지 않습니다.

1. **적용 범위**: 샘플 목적·핵심 동작·지원 범위.
2. **기술 스택과 버전 기준**: 샘플의 실제 버전·잠금 파일·명령·지원 조건.
3. **디렉터리와 파일명**: 실제 트리·대소문자/접미사 규칙·전체 직접 관리 파일 역할 표.
4. **의존 방향과 데이터 흐름**: 요청/화면 진입부터 결과·오류까지 실제 연결 경로.
5. **기능 작성 방식**: 새 기능 파일 위치·역할·이름·조립·공유 계약·테스트 연결 순서.
6. **설치·실행·검증**: 작업 위치·정확한 명령·예상 결과·종료·포트 변경.
7. **보안·변경 경계**: 입력/응답 검증·설정/데이터 보존·생성 파일·비밀값·생략한 운영 기능.
8. **새 프로젝트로 사용**: 복사할 코드·문서·지침·치환 항목과 검증 순서.
9. **예외·검증 결과**: 실제 검사 환경·결과·미검증과 남은 한계.

### 폴더·파일 역할 목록

샘플 전체의 직접 관리 파일을 실제로 읽어 목록화합니다. 소스뿐 아니라 진입점·DI·모델·설정·스크립트·테스트·버전 파일·manifest·잠금·ignore도 포함합니다. node_modules·vendor·빌드 결과는 제외합니다.

| 열 | 기록할 내용 |
| :--- | :--- |
| 경로 | 샘플 루트 기준 실제 경로·대소문자 |
| 역할 | 무엇을 입력받아 처리·반환하는지 또는 설정하는지 |
| 주요 구성 | 주요 클래스·함수·export·설정 키의 책임 |
| 연결 | 호출자·주입 위치·사용처·검증 테스트 |

“Service 파일”처럼 이름을 반복하는 설명은 피합니다. 역할별 표로 나눠도 직접 관리 파일은 누락하지 않습니다. 새 기능 추가 시 바꿀 조립·계약·테스트 위치까지 연결합니다. 단지 폴더 모양을 흉내 내기 위한 빈 파일·계층은 만들지 않습니다.

### 4절의 필수 아키텍처 소제목

아키텍처는 파일 트리·역할 목록이나 “MVVM·DI를 사용한다”는 문장으로 대체하지 않습니다. 다음 여섯 소제목을 docs/boilerplate.md의 4절에 작성합니다.

| 소제목 | 필수 내용 |
| :--- | :--- |
| 구성과 실행 경계 | 서버·클라이언트·프로세스·런타임·데이터 소유 범위 |
| 폴더와 계층의 대응 | 실제 경로·역할/계층·공개 인터페이스·의존 대상 표 |
| 의존 규칙 | 허용·금지 방향과 실제 파일 예시. import와 HTTP/IPC 호출 구분 |
| 진입·조립·수명주기 | 시작·DI·상태/설정 소유·시작 실패·종료/해제 |
| 정상·오류의 전체 흐름 | 대표 입력부터 응답·상태·화면까지 실제 파일/함수의 연결 |
| 구조도와 설계 선택 | 실제 경로의 Mermaid 의존 구조도·흐름도 각 1개, 현재 구조의 선택 이유 |

없는 계층·저장 단계는 만들지 않고 해당 없음의 이유를 설명합니다. 그림의 화살표가 소스 의존인지 실행 호출인지 명시하고 코드와 대조합니다. Mermaid 렌더링을 확인하지 못했다면 확인한 수준을 기록합니다. README에는 요약·상세 절 링크, 작업 지침에는 변경 시 지킬 경계·금지 의존을 반영합니다.

## 6. project-agents.md 작성

다음 6개 절로 **샘플 작업 지침**을 작성합니다.

1. 범위·작업 루트·README/docs 링크
2. 작업 전 지침·상태·연결된 코드·영향 확인
3. 실제 구조·명명·역할 경계·기존 구성 재사용
4. 최소 완결 변경·에러 처리·보안·사용자 변경 보존
5. 실제 설치·실행·검증 명령과 변경별 확인
6. 완료 기준·실행 결과·미검증·위험 보고

원본 제품에만 있는 클래스·API·장비·화면·명령을 지시하지 않습니다. 현재 샘플에 없는 테스트·설정·계층을 존재하는 것처럼 기록하지 않습니다. 상세 설명은 docs로 연결하고 같은 내용을 복제하지 않습니다.

## 7. 최소 실행 샘플

boilerplates/minimal/만 따로 복사해도 버전·의존성 복원 후 실행·테스트할 수 있어야 합니다. 실제 도구로 생성한 lockfile을 포함하고 설치 결과·빌드 결과·자격증명은 제외합니다. 원본 테스트 도구·프레임워크를 우선하되 불필요한 의존성을 줄입니다.

| 유형 | 최소 흐름 | 검증 |
| :--- | :--- | :--- |
| mobile-app | 화면 → 상태/조회 → 결과 | 상태 또는 위젯 테스트·실기기 검증 구분 |
| server | 요청 → 검증·처리 → 응답 | 정상·잘못된 입력 응답 |
| server-wui | UI → 서버 → 결과·오류 표시 | API·UI 대표 동작·브라우저 연결 |
| electron-app | renderer → preload/IPC → main → 결과 | IPC 검증·오류·실제 창 실행 |

운영 DB·클라우드 계정·제품 비밀값 없이 기본 실행이 가능하게 합니다. 외부 서비스가 필수면 로컬 실행 구성과 데이터 초기화 범위를 설명합니다. 포트 변경 시 서버·프록시·UI를 어떻게 맞추는지 안내합니다. GUI가 없는 환경에서는 해당 동작을 미검증으로 기록합니다.

샘플 README는 선행 환경·정확한 설치/실행/테스트/빌드/종료 명령·예상 결과·포트 변경·최소 구조·검증 환경을 담습니다. 샘플만 분리했을 때 docs 없이도 실행 안내를 읽을 수 있어야 합니다.

## 8. 링크·근거·라이선스

내부 링크는 모두 반출 폴더 안에서 해결돼야 합니다. 원본 소스를 가짜 로컬 링크로 만들지 않습니다. 산출물은 현재 샘플만 설명하며 원본의 출처·조사 커밋·비교·추출 이력을 싣지 않습니다. 법적으로 필요한 라이선스·저작권 고지는 유지합니다.

원본·외부 자산의 재사용 권한과 필요한 저작권 고지를 확인합니다. 라이선스를 확인하지 못했으면 기록하고 재배포 가능하다고 단정하지 않습니다. 기존 유형 결과에 없는 기능을 만들기 위해 의존성을 임의 업그레이드하지 않습니다.

## 9. 완료와 반입

- 유형명 폴더 전체를 임시 위치로 복사해 파일·링크·코드 블록·설정 문법을 검사합니다.
- 설명서 역할 목록과 실제 파일 목록·export·호출 관계가 일치하는지 확인합니다.
- 복사본 샘플에서 의존성 복원·테스트·타입 검사·빌드·기동·종료를 확인합니다. 명령이 없는 경우를 숨기지 않습니다.
- 실제 브라우저/GUI와 비UI 검증을 구분합니다. OS·CPU·도구 버전·명령·결과·미검증 이유를 기록합니다.
- 원본 프로젝트의 제품 파일이 바뀌지 않았는지 git diff로 확인합니다.
- node_modules·dist·캐시·비밀값·불필요한 임시 파일이 반출 폴더에 없는지 확인합니다.
- README·docs·지침·샘플의 구조·버전·명령·링크가 일치해야 합니다.

### 요구사항 대조표

docs/boilerplate.md의 9절에 요구사항 / 실제 파일·절 위치 / 검증 방법·결과 / 상태를 기록합니다. 상태는 충족·미충족·미검증·해당 없음으로 구분하고 해당 없음에는 이유를 적습니다.

행에는 네 산출물, 직접 관리 파일 전체 역할·명명, 아키텍처 여섯 소제목 각각, 새 기능 추가, 버전 관리, 독립 설치·실행·테스트·빌드·종료, 링크·설정 문법을 포함합니다. 원본 미변경 여부는 패키지 설명서가 아닌 최종 작업 보고에서 확인합니다. 각 문서 항목은 실제 내용·경로와 대조하고 실행 항목은 명령·결과로 확인합니다. 테스트 통과로 빠진 문서를 충족 처리하지 않습니다.

작성 중 확인된 문서·코드 누락은 작업 범위에서 보완합니다. 불가능한 검증은 조건·이유와 함께 남기고 전체 완료로 보고하지 않습니다. 최종 보고에서 대조표 위치와 미충족·미검증 항목을 명시합니다. 이 표는 누락을 확인하는 도구이며 자동으로 정확성을 보장하지 않습니다.

반입 시에는 완성된 유형명 폴더 하나를 02.Boilerplates/ 아래에 배치합니다. 기존 유형 자료가 있으면 무조건 덮어쓰지 말고 변경을 비교합니다. 이 저장소의 목록 README만 필요에 따라 갱신합니다. 원본 제품의 문서를 더 가져와야만 사용되는 상태는 완료가 아닙니다.
