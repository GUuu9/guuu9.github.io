# TypeScript Composer 변경 이력

## 2026-11-04 — npm 조합 생성 명령

- typescript-backend에 compose·test:compose 명령을 추가했습니다. 7개 결과 형태와 TCP·UDP·MQTT·Socket.IO 선택 기능의 파일·패키지·연결을 새 프로젝트에 생성합니다. 기존 대상과 템플릿 경로는 거부하고 원본·개인 환경·캐시는 보존합니다.
- 생성기에는 새 의존성이 없습니다. 출력 프로젝트의 새 manifest에 맞는 lock은 최초 npm install로 생성하며 기존 프로젝트의 lock을 삭제하지 않습니다. 생성된 앱은 묶음이나 생성기에 의존하지 않습니다.
- Node 24.22.1·macOS x64에서 생성기 테스트 3개, 7개 preset 및 Socket.IO 추가 조합의 빌드·테스트를 확인했습니다. 조합 검증에는 이전 임시 검증 프로젝트의 의존성을 링크해 사용했으며 각 결과의 새 npm install은 반복하지 않았습니다. 실제 Electron GUI·외부 배포·다른 OS는 이번에 검증하지 않았습니다.

## 2026-11-04 — 조립형 보일러플레이트 묶음 통합

- 묶음 명칭을 TypeScript Composer로 정하고 99.Boilerplates에서 02.Boilerplates/typescript-composer로 이동했습니다. 뼈대와 base·targets·features를 한 단위로 내려받습니다.
- 공통 README·작업 지침·변경 이력을 추가하고, 저장소의 목록·작성 규칙·요청문·탐색 메뉴를 새 묶음 기준으로 갱신했습니다. 모바일 유형은 별도로 유지합니다.
- 기존 독립 TypeScript backend·server-wui·Electron 유형은 뼈대 단독과 해당 조합으로 대체합니다. 기존 사용자의 프로젝트를 자동 변환하거나 의존성을 업그레이드하지 않습니다.
- 코드·직접 버전·잠금 파일은 이번 이동에서 변경하지 않습니다. 이전 템플릿 프로젝트에 새 경로·파일을 통째로 덮어쓰지 말고 새 빈 프로젝트에 선택 구성품을 적용합니다. 복귀는 이전 소스·manifest·lock·산출물을 같은 릴리스로 사용하며 사용자 저장 데이터는 별도 보관합니다.
- 이동 전후 실행 파일·설정·테스트 내용 동일성, 링크·앵커·메뉴·설정·공백을 확인했습니다. 이번 이동으로 실행 테스트를 반복하지 않으며 실제 빌드·통신·미서명 앱 묶음 이력은 아래 파일을 유지합니다. 현재 PATH에 Jekyll CLI가 없어 웹 빌드·화면 검증은 수행하지 않았습니다.

## 2026-11-04 — feature 연결 선언과 충돌 검사

- 기능별 compose.json으로 패키지·명령·기존 파일 패치를 선언합니다. 기능 파일의 기존 경로 충돌, 패키지 버전/명령 충돌, 없거나 중복된 연결 원문은 출력 생성 전에 거부합니다.
- game-persistence는 DI의 gamePersistence로 등록하고 Electron 게임 IPC는 같은 인스턴스를 주입받습니다. Node 기본 데이터는 프로젝트 .local/game-save, Electron은 기존과 같은 userData입니다. 새 npm 의존성은 추가하지 않았습니다. 생성기 테스트 3개에서 두 기능의 동일 DI 추가 순서·연결 원문 불일치·파일/버전 충돌 거부를 확인했습니다. Node Service/통신·Electron 게임·Socket.IO+Service 조합의 타입 검사·빌드·테스트도 통과했습니다. 검증 의존성은 기존 임시 프로젝트를 재사용했습니다.

## 2026-11-04 — 사용자·관리자 문서 분리

- 루트 README와 사용자 가이드는 다운로드·형태/feature 선택·생성·시작만 안내합니다. 구조·작성·DI 패치 설명은 docs/maintainers로 옮기고 project-agents에 문서별 독자·책임을 기록했습니다.
- 묶음 루트에 의존성 없는 compose·test:compose 명령과 .nvmrc를 추가했습니다. 기존 typescript-backend 명령도 유지하며 출력 상대 경로는 실행한 작업 폴더 기준입니다.
- 사용자/관리자 웹 메뉴·문서 링크를 갱신했습니다. 루트 명령과 생성기 테스트 3개를 확인했습니다. 실제 GUI·원격 배포·다른 OS 검증은 이번 변경 범위에 포함하지 않습니다.

## 2026-11-04 — Feature 작성 규칙

- 관리자·AI용 Feature 작성 규칙에 폴더/파일 계약·코드 책임·선행 조건·DI 패치·패키지/환경/데이터 보존·등록·완료 검사를 명시했습니다. 단순 util 양식과 기존 Service·통신 선언을 예로 연결했습니다.
- 문서 책임을 분리하고 기존 구조 문서의 상세 패치 설명은 전용 규칙으로 모았습니다. 저장소 AGENTS·묶음 project-agents·구성품 목록·웹 메뉴에서 연결합니다.
- 문서 링크·앵커·코드 펜스·JSON 예제·YAML·공백을 정적으로 확인했습니다. 실행 코드·패키지 설정은 변경하지 않아 실행 테스트를 반복하지 않았습니다.

## 2026-11-04 — 프로젝트명 기준 생성 위치 고정

- typescript-backend에서 형태·프로젝트 이름만 지정하면 복사한 Composer 바로 아래에 프로젝트를 생성합니다. 묶음 루트의 별칭·다른 cwd에서도 위치는 같습니다. 절대/상대 경로 인자는 이름 전용 형식으로 대체했습니다.
- 기존 대상·템플릿 예약 이름·경로 입력을 거부합니다. 테스트는 임시 묶음을 복사해 사용하므로 실제 뼈대나 프로젝트를 변경하지 않습니다. 생성기 테스트 4개로 preset·feature·충돌·개인 환경·cwd 독립 위치를 확인했습니다.
- 향후 기존 프로젝트 feature 추가도 같은 이름 기준으로 대상을 찾을 수 있도록 문서 규칙을 맞췄습니다. 해당 추가 명령 자체는 아직 구현하지 않았습니다. 앱 실행 코드는 변경하지 않았습니다.

## 2026-11-05 — 프로젝트 내 feature 추가

- 생성된 프로젝트에 feature 명령·로컬 구성품 원본·활성화 상태를 포함합니다.
- add 명령은 기존 기능을 유지하며 변경분·연결·의존성을 적용하고 설치/검사/테스트/빌드를 수행합니다.
- 충돌은 쓰기 전에 중단하고 검증 실패 시 소스·manifest·lock·상태를 복구합니다. 외부 설치 작업·node_modules·빌드 산출물은 복구하지 않습니다.
- feature 작성 규칙에 생성 후 자동 연결과 회귀 검사 의무를 추가했습니다.

- 검증: Node 회귀 검사 5개 통과, JSON·Markdown 상대 링크·코드 펜스·공백 검사 통과. 설치/검증 성공·실패는 모의 npm으로 검사했으며 이번 변경의 실제 의존성 설치·앱 빌드·GUI는 미검증입니다.
